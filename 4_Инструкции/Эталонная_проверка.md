# Эталонная проверка (регресс-тест) «Однолинейки»

Папка: `5_Проверка/`. После правки формул или структуры книги одна команда показывает,
изменились ли результаты на эталонах v3.11 (`Однолинейка_пример_ЖК-Остров.xlsx`, `Объект ЖД/Однолинейка ГРЩ-ЖД.xlsx`).

## Как запускать (из папки `5_Проверка/`, Python 3 + `pywin32`, `openpyxl`, Excel)

```
py check.py                                   # оба эталона; ~25 с; код 0 = без изменений, 1 = есть изменения/ошибка
py check.py --etalon ostrov                   # один эталон (ostrov | grsh_zhd)
py check.py --book Новый_шаблон.xlsx --etalon ostrov   # другую книгу против baseline эталона
py check.py --update-baseline                 # принять текущее состояние как эталон (обоих или --etalon X)
py check.py --log SX_log.txt                  # сверить журнал LISP с ожиданиями (без Excel)
py check.py --log SX_log.txt --book Книга.xlsx         # то же, но ожидания берутся из пересчёта этой книги
py check.py --full --report otchet.txt        # полный отчёт (по умолчанию ~70 строк, до 10 строк на раздел)
py snapshot.py Книга.xlsx -o снимок.json      # только снимок
```

Пересчитывается КОПИЯ книги (исходник не меняется): Excel COM (отдельный экземпляр, невидимый),
`CalculateFull`, внешние связи не обновляются (значения из кэша связей), Excel закрывается в `finally`
(`Quit`, при зависании убивается только свой PID). Если Excel недоступен: LibreOffice headless,
затем кэш openpyxl (без пересчёта, с явным предупреждением в отчёте). Числа сравниваются с допуском 1e-5.

## Что снимается (baseline/*.json, ~40-70 КБ)

| Раздел | Источник |
|---|---|

| Ошибки в ячейках | по листам и столбцам: число `#Н/Д`, `#ЗНАЧ!`, `#ССЫЛКА!`… (в шаблоне их тысячи «по дизайну» — сравниваются числа) |
| Однолинейка | рисуемые строки (BD=1 + линия/автомат/канал/клемма), ключ «щит \| место»: C, G, H, M, O, P, Q, R, T, U, V, W, X, Z:AE и служебные BD–BM |
| Статус (светофор) | AE1 и число строк по каждому тексту статуса AE |
| Исходные данные | по линиям (D): мощность, длина, ток, автомат, сечение, потери, группа Кс, ΔU от ВРУ, Iкз/отключение (BI:BM) |
| Нагрузки щита | «Нагрузка_щитов», блоки AE (Руст, Руст быт, Кс быт, Рр сил, Рр пост, Рр, Кс итоговый, Iр) по щиту / секции 1 / секции 2, V5:V9, Р по фазам |
| ПЗ, питание, нижестоящие | «Расчёт_нагрузок», «Питание_щита», «Нижестоящие_щиты» (связи ГРЩ) |

| Категории и шины (v3.12) | «Исходные данные» BN:BV по линиям: категория (ввод и итог), пожарная, шина, тип шины, источник, обеспечена, проверка |
| Схема щита (v3.12) | «Питание_щита»: схема щита C65:E69, «Шины щита» B73:D82, итоги по категориям для вышестоящего J44:S47 |
| Режимы (v3.12) | лист «Режимы»: режимы × источники (Руст, Кс, cos φ, tg φ, Pр, Qр, Sр, Iр, слагаемые), по категориям, необеспеченные линии, сверка с «Нагрузка_щитов» |

| Счётчики | «Справочная» BE8:BF16 (автоматы, QFD, XT, модули, ошибки/предупреждения, необеспеченные категории) + пересчёт: линии, различные QF, XT, модули, листы схемы |

## Когда обновлять baseline

- Изменение ожидаемое и проверено глазами (новая формула, поправка нормы, новая версия шаблона): посмотрите отчёт `py check.py`,
  затем `py check.py --update-baseline` (отчёт о том, что менялось, печатается до записи).
- Не обновляйте baseline, чтобы «позеленело» без разбора. Изменилось «Руст», «Кс», «Iр» или число автоматов без причины: это регресс.
- Новый шаблон: перенесите данные эталона в новый файл, `py check.py --book Новый.xlsx --etalon ostrov`;
  различия только в тех полях, где формулы изменены намеренно. После принятия — `--update-baseline` (книги эталонов также обновить в репозитории).
- baseline лежит в git вместе с кодом; `.gitignore` в `5_Проверка/` закрывает `__pycache__`, `*.snapshot.json`, временные копии.

## LISP: журнал SX_log.txt (`chats/2026-09-26_single-line-excel-autocad/2_AutoCAD/Однолинейка/SX_Schema.lsp` v3.7, LISP не менялся)

В журнал пишутся: `rows read=`, **`recs=N draw=M`** (строки выбранного щита / с BD=1), **`sheets=(…)`** (индексы листов схемы с содержимым, с 0),
`first place … row=("ЩР" …)` (имя щита), `block XX OK/MISSING`, `ERROR …` (сбои этапов), `FATAL …`. Итоговых счётчиков
нарисованного (автоматов, клемм, линий, модулей) **нет**. `--log` сверяет `recs`, `draw`, `sheets` с пересчётом книги и считает ошибкой любые
`ERROR`/`FATAL`; `block … MISSING` — предупреждение. Проверено на синтетическом журнале (реального SX_log.txt в репозитории нет).

**Что добавить в LISP** (одна строка в конце `sx:main`, перед `sx:logdump`), чтобы сверять и результат отрисовки:
`SUMMARY panel=ЩР qf=35 xt=49 mod=1 lines=52 sheets=4 ent=NNNN` — число вставок блоков QF1 / XT / модулей на слоях `SX_*`
(`ssget "_X"` по слою и имени блока), число линий с `hasline`=1, число листов. Тогда в `check.py` достаточно сравнить
эти числа с `счётчики → пересчёт по «Однолинейке»` (qf, xt, mod, lines, sheets уже есть в снимке).

## Ограничения

- Нужен установленный Excel для честного пересчёта; на других машинах (LibreOffice/кэш) возможны мелкие расхождения.
- Внешние связи не обновляются: «Диапазоны» и «Нижестоящие_щиты» берут кэш связей — изменение файлов нижестоящих щитов не видно, пока связи не обновлены и книга не сохранена в Excel.
- Ключ строки «Однолинейки» — номер места (B): при перенумерации строки покажутся как «исчезла/появилась».
- Ошибки в шаблоне «по дизайну» (`#Н/Д` в пустых строках, `#ССЫЛКА!` 874 в «Нагрузка_щитов», `#ЗНАЧ!` в «Расчёт_нагрузок» C56:C58) записаны в baseline как есть — это зафиксированное состояние, а не одобрение.
- Спецификация «вручную» («Спецификация», без формул) не снимается — только «Спецификация_авто».
- Геометрия чертежа (координаты, слои) не проверяется — только данные, из которых LISP рисует.

## Независимый пересчёт сборки ГРЩ

`py _Разработка/2026-09-29_speedup-automation/scripts/verify_rollup.py "1_Таблицы_Excel/Объект ЖД"` пересчитывает в Python (без Excel) объектный итог по категориям, пожарным и Руст по щитам из линий книг и сверяет с листами «Режимы» и «Категории_по_щитам» ГРЩ (допуск 1e-6). Проверено: на данных по умолчанию (всё III) и на тестовой копии с категориями I особая / I / II, пожарной линией и линией на шине ИБП — совпало.
