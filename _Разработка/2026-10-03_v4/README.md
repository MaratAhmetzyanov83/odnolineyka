# Однолинейка v4 — архитектура

Начато 03.10.2026. Решения пользователя: Microsoft 365 у всех, **один файл на объект**, кабельный журнал в AutoCAD через Data Link (→ лёгкая выгрузка), методика расчёта в книге + документ + пояснения в заголовках, все расчёты по нормам РФ (см. `4_Инструкции/Методика_расчёта.md`), бытовая нагрузка частного дома — «дом повышенной комфортности» (СП 256 табл. 7.2 + Изм. 9), kп.к — настройка объекта (по умолчанию 1).

## Цели

1. **Один лист ввода.** Всё про линию — в одной строке, слева направо в порядке заполнения.
2. **Один файл на объект.** Все щиты в одной книге, ГРЩ собирается формулами, внешних связей нет.
3. **Лёгкая книга.** Таблицы Excel (ListObject): формулы только в строках с данными, а не до 1000-й строки.
4. **Нормы РФ.** Методика v4 = методика v3.12 + исправления из `Методика_расчёта.md`; режим совместимости v3.12 для сверки.
5. **AutoCAD без переделки.** Лист «Однолинейка» остаётся с той же раскладкой столбцов (интерфейс для SX_Schema.lsp и SX_Layout.lsp), но становится расчётным.
6. **Всё понятно инженеру.** Лист «Гайд», лист «Методика», примечание к заголовку каждого расчётного столбца, лист «Проверка».

## Как избежать циклических ссылок в одной книге

ГРЩ суммирует нижние щиты, а нижние щиты берут у ГРЩ ΔU и Zпетли. Ссылки «щит → вся колонка щитов» создают цикл. Решение:

- **Путь щита** (`Щиты[Путь]`, например `|ГРЩ|ЩР-1|ЩР-1.1|`) считается только из столбцов ввода «Питается от» итеративно (LET / REDUCE) — без цикла.
- **Нагрузка вверх:** у каждого щита считаются **собственные составляющие** (Руст быт, Рр сил = Σ P·Кс, Руст пост, Σ P·cos φ, Σ Q, отопление, ВНГ; для категорий и пожарных — отдельно) только по своим линиям, где фидеры дают 0. Итог щита = сумма собственных составляющих всех щитов, в чьём пути есть этот щит: `SUMIFS(Щиты[Руст быт собств.], Щиты[Путь], "*|"&[@Щит]&"|*")`. Кс быт и Ко применяются к итогу (составляющие аддитивны, как в `grsh_rollup.py`).
- **ΔU и Z вниз:** у фидера считаются ΔU и петля **своего кабеля** (ток фидера = Iр нижнего щита). ΔU до шин щита = Σ ΔU фидеров на пути + ΔU внешней сети; Zшин = Zсети + Σ (петля фидера + Rпер) на пути.
- Столбцы линии «мощность для расчёта» и «мощность ввода» разделены: составляющие берут только ввод, фидер берёт итог нижнего щита.

## Порядок работ

1. Макет: `build_v4.py` собирает книгу через Excel COM; `migrate_v3.py` переносит объект v3.12 (папка из N книг) в одну книгу v4.
2. Режим совместимости v3.12 → сверка с объектом ЖД и примером ЖК‑Остров (токи, номиналы, сечения, ΔU, Руст, Рр, Iр).
3. Исправления по нормам (переключатель «методика: v3.12 / нормы 2026»).
4. Режимы, категории, ИБП, ПЗ, журнал, спецификация.
5. Однолинейка-интерфейс → проверка SXDRAW / SXLAYOUT в AutoCAD.
6. Гайд, Методика, примечания, Проверка.


## Состояние на 04.10.2026 (бета)

Готовые книги: `1_Таблицы_Excel/v4 (бета)/` — шаблон, пример ЖК‑Остров, объект ЖД (все 17 щитов в одном файле).

**Скрипты** (`scripts/`):
- `extract_v3.py` — перенос введённых данных из книг v3.12 (папка объекта или одна книга) в JSON: линии, места, щиты, фидеры, фазы, справочники (объединение: при разных определениях кода берётся вариант книги, где код используется), результаты v3.12 для сверки;
- `build_v4.py` — сборка книги v4 через Excel COM (`--mode v3.12` для сверки, по умолчанию «нормы 2026»); в конце сверка с v3.12 по линиям и щитам;
- `guide_v4.py` — лист «Гайд» (ASD-STE100), `methodology_sheet.py` — лист «Методика» из `4_Инструкции/Методика_расчёта.md`;
- `make_journal_bas.py` — макрос `3_Макросы_Excel/SX_Journal.bas` («Выгрузить журнал» для Data Link).

Пример: `py extract_v3.py --folder "<папка объекта v3.12>" --out obj.json` → `py build_v4.py --data obj.json --base "<книга ГРЩ v3.12>" --out "<Однолинейка_v4_объект.xlsx>"`.

## Доработки по замечаниям пользователя (04.10.2026)

- **Гайды на листах:** «Объект» (снизу — что значит каждая настройка), «Щиты» и «Шины» (сверху, над таблицей).
- **«Щиты»:** ввод разделён на «схема щита» и «только для ВРУ/ГРЩ»; результат — главные столбцы, подробности свёрнуты. «Питается от» — автоматически по линии-фидеру. Новое поле «Мест под вводной узел» (по умолчанию 15; при переносе — по первой рисуемой линии).
- **«Линии»:** наименование подставляется по коду и переписывается вручную в той же ячейке; фидер определяется сам (номер линии = имя щита), «Питает щит» — только если номер другой; № места пусто = следующее по порядку после вводного узла, число — своё место, «-» — нет на схеме; столбец «Лист / место»; строки вводного узла по умолчанию не рисуются (режим «рисовать»); щиты разделены цветом и линией, листы схемы — пунктиром.
- **Дифзащита (мА)** вместо «30 мА»: 10 / 30 / 100 / 300, «нет», «да» = 30; текст автомата «2P С16А 10мА»; в группе — самая строгая уставка; «Каталог» понимает числа.
- **«Итоги_щитов»:** карточка щита (как блок «Нагрузка_щитов» v3.12: Руст, Кс, Рр, cos φ, Iр, фазы, L1р–L3р, перекос, Iпуск, КРМ) + таблица всех щитов.
- **«Режимы»** (было «Нагрузки») — с пояснением, как читать.
- **Кабельный журнал** — раскладка v3.12 (маркировка, трасса, кабель по проекту / проложено, испытания, дата), без «L=…%»; гофра с диаметром.
- **«Однолинейка»:** щиты разделены, вводной узел подсвечен, служебные столбцы свёрнуты; строки «нет на схеме» сюда не попадают.
- **Спецификация:** выбор щита — «Спецификация» D1; «Спецификация_авто» видна.
- **Бирки:** строка на каждый провод (QF → устройство → канал модуля → клемма → кабель), общие участки — один раз.
- **«Справочная» → «Таблицы_норм»:** старые коды/УГО/этажи/кабели убраны (они на листе «Коды»).
- **Пример «все случаи»:** `1_Таблицы_Excel/v4 (бета)/Однолинейка_v4_пример_все_случаи.xlsx` (данные — `scripts/make_demo.py`).
- Исправлено: в группу попадала строка «нет на схеме»; одинаковые имена служебных столбцов; проверка «фидер ниже нагрузки» для нагрузки шин ИБП/ДГУ (для фидера считается как I).
