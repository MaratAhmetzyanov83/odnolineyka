# 2026-10-03 Компоновка щита (SXLAYOUT) v0.1

Задача: кроме однолинейки, строить из той же книги визуализацию компоновки щита (вид спереди).
Решения пользователя: AutoCAD, новая команда; корпус — подбор и ручной выбор; на компоновке модульные аппараты,
клеммы и шины, габариты и надписи, немодульное оборудование; порядок — по типам.

## Файлы

| Файл | Что это |
|---|---|
| `src/SX_Layout.src.lsp` | исходник с русскими строками в виде `(R "…")` |
| `src/SX_Layout.src.dcl` | окно (UTF-8) |
| `src/build.py` | сборка: `(R "…")` → `(sx:ru '(коды))`, проверка скобок и ASCII в литералах; DCL → Windows-1251 |
| `output/Пример_ЖК-Остров_*.png/.dwg` | результат на примере ЖК-Остров с базой пользователя |

Сборка: `py src/build.py` → `2_AutoCAD/Компоновка/SX_Layout.lsp` (UTF-8, CRLF) и `SX_Layout.dcl` (cp1251, CRLF).
Править только `src/`, собранные файлы не редактировать.

## Как проверялось

AutoCAD 2027 есть на машине. Проверка без окна (скрытый экземпляр через COM и отдельный скрытый Excel, чтобы не трогать
открытые книги пользователя): `sxl:batch` на копии `Однолинейка_пример_ЖК-Остров.xlsx`, затем `DXFOUT` через
`accoreconsole` и рендер ezdxf.

1. Автоподбор → CQE 2000x800, 9 реек из 9, без ошибок. Блоки подобрались: ZIOMB24V2 → ZIO-MB24_ATT_DEF, NB1L → DS201,
   NB1-63 1P → S201, МК-5-1 → MR-5-1, VPR-2.5-3L-GY. Перечень: XT1-XT24, XT28-XT52 (52 шт.), QFD1-QFD4, QFD6-QFD28 (27),
   QF29-QF35 (7) — сходится со «Спецификацией_авто».
2. Ручной корпус ЩРН-П-72 → 34 позиции не поместились, нарисованы красным под корпусом, замечания выведены.
3. Каталог с блоками в Q для «Прочее» (R5MTHNO → TGW735i, R5RV12230 → ZDI-DLI) → аппараты на монтажной панели под
   рейками, подбор ушёл на CQE 2000x1000.
4. `SXLUPDATE` на сохранённом чертеже → то же число объектов, старая компоновка удалена.

Окно (DCL) в скрытом режиме не открывалось — проверить руками: `SXLAYOUT`, все кнопки «Обзор», «Указать точку».

## v0.2 (04.10.2026): база корпусов DKC и ограничения по месту

- Исправлено: блоки S201/DS201/ZIO-... рисовались белыми прямоугольниками — CopyObjects переносит таблицу ACAD_SORTENTS
  со ссылками на объекты базы. `sxl:fix-draworder` берёт полный порядок прорисовки из блока в базе (GetFullDrawOrder,
  по номеру объекта) и задаёт его блоку в чертеже (SetRelativeDrawOrder). Проверено только чтением чертежа пользователя
  (таблица есть, заливка последняя); перерисовку пользователь должен подтвердить.
- Загрузка SX_Schema: поиск в соседней папке «Однолинейка» (по SXL_LibDwg / SX_DclFile / SXL_DclFile), отказ грузить
  файл с другим именем (пользователь выбрал SX_Layout.lsp в окне «SX_Schema.lsp» — отсюда «неверная функция SX:XL-RELEASE»).
  Окно SX_Layout.dcl тоже ищется рядом.
- База корпусов `2_AutoCAD/Компоновка/SX_Корпуса.csv` (222 строки) из `data/*.json`, собранных с dkc.ru во встроенном
  браузере: списки разделов 652 (ST), 170/255 (STE), 2096 (CQE N, «собранный корпус»), карточки 117 (RAM Base ЩРн-п IP65),
  2087/2088 (FRAME). Дубли по размеру сведены к основному артикулу. Генератор `src/make_encl_csv.py`.
- Окно: ограничения Ш/В/Г «не более», установка, серия; список корпусов фильтруется на лету; выбор и ограничения
  в ldata. Подбор: с запасом самый маленький по площади (в нём типы с новой рейки, иначе подряд), потом без запаса.
- Проверено в accoreconsole (чистый LISP, без COM): чтение CSV UTF-8 (222), фильтры (навесной 131, встраиваемый 5,
  напольный 86, ST и Ш<=500 — 25, Г<=120 — 14), подбор на синтетическом наборе (ST 600x800x300 без ограничений,
  CQE N 1400x600x400 для напольного). Найдены и исправлены: `sxl:fnum` возвращал T; переменная H затирала файл h.
- НЕ проверено в AutoCAD с окном (у пользователя открыт свой AutoCAD, COM подключился бы к нему): окно DCL,
  отрисовка корпусов MOD/PLATE.
