# Архитектура программы «Объект»

## Слои

```
           окно (браузер)          ui/static: app.js, views/*.js
                │  HTTP 127.0.0.1
             ui/ (server.py, routes.py)          — API: @route
                │
          services/ (project.py — конвейер)      — загрузка, связи, кэш, правки
           │        │         │         │
       sources/  checks/    calc/     core/
       адаптеры  правила    расчёт    модель, правки, отпечатки, JSON
```

Правило зависимостей: стрелки только вниз. `core` не знает ни о чём. `checks` и `calc` знают только `core`.
`sources` знают `core` и свой формат файла. Окно получает только JSON.

## Модель (`core/model.py`)

Объект → Документы → Щиты → Линии. Замечания — отдельный список объекта.

У линии и щита три части:

| Часть | Что | Кто меняет |
|---|---|---|
| `input` | ввод инженера: P, L, марка, жилы, Кс… | инженер (правки) |
| `scheme` | что на схеме: место, QF, автомат, клемма, шина | инженер / подбор |
| `result` | расчёт: Iр, сечение, ΔU, Iкз, категория, статус | расчёт; `result.by` = `excel` или `python` |

`refs` — где поле лежит в источнике (`Ref`: файл, лист, ячейка). По нему окно открывает Excel на нужной ячейке,
по нему же будет запись правок.

Связи — по id (строки): `panel.parent`, `panel.parent_line`, `line.feeds`. Модель без потерь пишется в JSON.
Новое поле — всегда со значением по умолчанию: старый кэш и JSON читаются (`serialize.from_dict`).

## Конвейер загрузки (`services/project.py`, `STEPS`)

`read` (адаптеры, кэш по дате файла) → `link` (связи щитов) → `calc` (пока пусто) → `revision` (отпечатки) → `checks`.
`recheck(prj)` — всё, кроме чтения: после правок в памяти.

## Как расширять

**Новая проверка.** Функция в `checks/<тема>.py`:

```python
@rule("links.my_check", "Короткое название", group="Связи щитов")
def my_check(prj):
    for p in prj.panels():
        if ...:
            yield Hit(2, "текст замечания", p.id, line_number, ref)
```

Новый файл правил — добавить в импорт `checks/__init__.py`. Тест — в `тесты/test_core.py` (объект собирается в коде).
Окно само покажет правило в фильтрах (группа) и в столбце «Проверка».

**Новое поле из книги.** Поле в модель (`core/model.py`, со значением по умолчанию) → адрес в
`sources/excel_v312/layout.py` (`SRC_FIELDS` / `ODN_FIELDS` / …). Тип берётся из модели сам.

**Таблица поменялась** (новый столбец, сдвиг строк) — править только `layout.py`.

**Новый источник** (свой файл объекта, другая версия таблицы, DWG). Класс-наследник `sources.base.Source`:
`can_read`, `read`, при необходимости `write`, `open_at`; `register(...)`; импорт в `sources/__init__.py`.

**Расчёт в Python.** Модули в `calc/` (договор — в `calc/__init__.py`), вызов из `step_calc`.
Результат — в `result`, `result.by = "python"`. Сверка с Excel по каждой линии, пока не совпадёт.

**Правки из окна.** Поле — в `core/changes.py` `FIELDS` (тип, разрешено ли, список вариантов) и адрес — в
`layout.py` (`SRC_EDIT` / `ODN_EDIT` / `NET_EDIT`). Столбцу окна — `edit: {path}` (`static/js/columns.js`).
Путь: окно копит правки (`js/pending.js`) → `POST /api/edit` → `services/edit.py`: `changes.apply` (тип, права),
проверка даты файла, резерв, `Source.cells_for` + `Source.write` (Excel: свой скрытый экземпляр, `writer.py`),
журнал → окно перечитывает объект. Отмена — `undo_last`: обратные правки последней записи.
Автотесты пишут через openpyxl (`ODN_TEST_WRITER=1`) — только на тестовых книгах.

**Таблица окна** — `static/js/grid.js`, один модуль на все таблицы: `mount(host, {key, columns, rows, rowRef…})`.
Новые возможности таблицы (свои условия, новые итоги) — там; новые столбцы — в `columns.js` или в экране.

**Актуальность DWG / КЖ.** `core/revision.py` — отпечаток данных щита. SXDRAW и «КЖ в DWG» пишут его в чертёж;
новый источник `sources/dwg` читает отметку; правило `artifacts.stale` сравнивает.

**Новый запрос API.** Функция с `@route("POST", "/api/...")` в `ui/routes.py`; в окне — функция в `static/js/api.js`.

**Новый экран / вкладка / карточка.** Экран — модуль `static/js/views/<имя>.js` (`render(ctx)`, `bind(root, rerender, ctx)`)
и строка в `VIEWS` (`app.js`); адрес — в `nav.js`. Вкладка — элемент `TABS` экрана; карточка щита — элемент `CARDS`.
Переходы — атрибут `data-go="#/..."`, открыть в Excel — `refLink(ref)`.

## Тесты

```
py -m unittest discover -s тесты -v
```

- `test_core.py` — модель, правки, отпечатки, все правила; без Excel, доли секунды.
- `test_excel.py` — чтение книг на тестовом объекте `make_demo.py` (строится один раз, ≈30 с; папка — `ODN_DEMO`).

Правило: новая проверка или поле — новый тест. Перед отправкой — все тесты зелёные.
